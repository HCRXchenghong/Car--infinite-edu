# VCU 固件工程状态

当前目录尚无可编译、可烧录的 VCU 固件。不得把 `.gitkeep` 或总体设计中的软件分层视为已经完成实现。

## 建立工程前的入口条件

- STM32G474 完整 Pinmap、时钟树、DMA/中断优先级和安全相关 GPIO 默认态已冻结；
- 三条 CAN、CANopen、BMS、超声波、ToF、达妙电机和 nRF52840 主机协议已有受版本控制的协议文件；
- 上位机与无线遥控器的唯一控制权仲裁、武装/死手、超时和模式切换已冻结；
- 四个驱动轴和四个转向轴的硬件安全路径及故障反馈已完成原理图审查；
- 坐标系、单位、四轮映射、参数范围和标定流程已定义。

## 建议工程结构

```text
VCU/软件程序/
├── CMakeLists.txt 或工程配置
├── README.md
├── app/             状态机、控制权、运动学、故障策略
├── services/        通信管理、参数、诊断、日志、看门狗监督
├── protocols/       CAN FD、CANopen、BMS、传感器、无线协议
├── drivers/         FDCAN、SPI、MAX14830、UART、GPIO、Flash
├── bsp/             板级 Pinmap、时钟、电源和安全 I/O
├── bootloader/      镜像校验、版本、断电恢复和回滚
├── tests/           单元测试、SIL、协议回放和故障注入
└── tools/           参数生成、DBC/EDS 处理、日志解析
```

## 最低质量要求

- 固定工具链和依赖版本，构建可重复；
- 编译警告视为错误，启用静态分析和格式检查；
- 运动学、角度翻转、全轮等比例限幅、超时和控制权仲裁具有主机端单元测试；
- 不使用动态内存作为运行期基础依赖；中断只做采样、入队和置位；
- 安全关键任务与可降级服务分级，看门狗不因单个非关键传感器掉线反复复位；
- 保存固件版本、参数版本、硬件版本、复位原因和锁存故障；
- 在接机械负载前完成总线仿真、协议回放、断线、乱序、CRC 错误、超时和急停故障注入。
