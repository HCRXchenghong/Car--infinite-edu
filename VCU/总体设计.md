# VCU 教育版总体架构设计

> 文档状态：架构审查修订稿 v0.2（未达到原理图冻结条件）  
> 适用对象：四轮四转机器人底盘 VCU 教育版  
> 本文定义当前硬件候选、控制边界、安全目标、电源预算和板框目标；达妙电机、驱动器、BMS、超声波与 ToF 的厂家协议以及 Pinmap、安全链和机械资料到位后，才能冻结具体实现。

逐页原理图输入、实体脚表和纸质检验程序见 [HW-R1 硬件实施包](../硬件设计包/00_使用说明与放行边界.md)。该包对参考电路和建议 Pinmap 为当前基线，H 项关闭前不得投板。

## 1. 设计目标

VCU 是底盘的唯一运动控制中心。上位机只下发底盘级目标，不直接给单个电机下发角度、转速或转矩命令。VCU 负责：

- 接收上位机和无线遥控器的速度、模式、使能与复位指令；
- 执行四轮四转运动学解算；
- 控制四个转向关节电机与四个驱动轮；
- 接收 BMS、超声波、ToF、BCM 与电机反馈；
- 完成通信超时、急停、电子驻车、故障锁存和看门狗恢复；
- 向上位机和 BCM 上报底盘状态、传感器状态和故障信息。

系统按“上位机给运动目标，VCU 负责执行和安全”的原则设计。

上位机和无线遥控器不能同时拥有运动控制权。VCU 必须维护唯一控制源状态机，例如 `NONE / UPPER_COMPUTER / RADIO`；控制权切换只允许在车辆零速、所有来源命令已失效、目标模式明确且人工重新使能后进行。任何模式下都必须校验命令序号、新鲜度、死手开关和超时，禁止采用“最后到达的报文覆盖前一个来源”的策略。

## 2. 当前核心选型

| 功能 | 选型或约束 | 说明 |
|---|---|---|
| 主控 MCU | `STM32G474QET6TR` | Cortex-M4F，170 MHz，LQFP128，3 路 FDCAN，内置 IWDG 与 WWDG |
| CAN 收发器 | 3 路板载、支持 CAN FD 的工业/车规收发器 | 每条物理 CAN 单独配置 1 颗；CANopen 总线也可以使用 FD 收发器并运行经典 CAN |
| UART 扩展 | `MAX14830` × 3 | 每颗 4 路 UART、128-word 收发 FIFO；共提供 12 路扩展 UART |
| BMS 串口 | MCU 原生 UART | 不与传感器共享，保证电池状态通信优先级 |
| 2.4 GHz 无线 | 带 U.FL/IPEX 外置天线接口的 `nRF52840` 模块 | 用于后续自研低延迟双向遥控器和无线安全停止 |
| 本地急停 | 两线、常闭回路、硬件优先 | 教育验证基线；按下急停或线缆断开均应进入急停，且必须覆盖 4 个驱动轴和 4 个转向轴 |
| 看门狗 | IWDG 为主、WWDG 为辅；预留外部硬件看门狗安全门控 | 软件失控时恢复 MCU，硬件链路保证电机不继续运动 |

`STM32G474QET6TR` 的 `TR` 表示卷带包装，适合量产贴片；样机可使用 `STM32G474QET6`。

### 2.1 电源预算和板框目标

VCU 只负责控制器、通信、传感器接口和安全信号，不给四个驱动轮或四个转向执行器提供动力电源。首版按外部 **12V 输入 3A 连续、5A 短时峰值**设计，覆盖 MCU、三路 CAN、3 颗 MAX14830、nRF52840、BMS、传感器接口和外部 5V 传感器供电的启动余量。

建议电源树为：

```text
外部 12V
   ├── 12V → 5V_LOGIC → 3.3V_LOGIC：MCU、MAX14830、nRF，目标 0.8～1A
   │           └── CAN 主电源 5V，VIO 使用 3.3V
   └── 独立 12V → 5V_SENSOR_RAW → 各端口限流/关断 → 传感器
               首样按 2.4A 连续、3A 峰值评估，超过需升级电源/散热
```

外部传感器电源不得与逻辑电源形成无保护的同一故障域。每个连接器或合理分组设置限流/短路保护、可关断高边和故障反馈；任一路传感器电源短路不得拉低 `3.3V_LOGIC` 或使安全门控失效。传感器电源默认关闭，待 MCU 自检完成后分组开启。

输入反接、汽车瞬态、TVS、滤波、欠压和上电时序必须按实际 12V 电源参数核对。若最终传感器由独立电源供电，VCU 输入预算仍按 3A/5A 保留，不因此缩小保护器件和连接器余量。

5V→3.3V 在 0.8～1A 目标下优先使用 Buck。若使用 LDO，必须提交最坏压差、电流、环境温度和 PCB 散热条件下的结温证明。

VCU 首版 PCB 目标外形为 **130 mm × 90 mm**。该尺寸较 120 mm × 80 mm 增加约 22% 面积，但在真实连接器、支路保护、安全门控、nRF52840 模块、安装孔和外壳 3D 模型导入前只能作为机械目标，不能宣称已经可行或冻结。

## 4. 三路 CAN 架构

三条 CAN 总线是彼此独立的物理网络，均由 VCU 板内置收发器、接口保护和终端匹配构成。

| 总线 | MCU 外设 | 连接对象 | 总线模式 | VCU 角色 |
|---|---|---|---|---|
| CAN-1 | FDCAN1 | 上位机、BCM | CAN FD | 底盘控制节点与状态发布节点 |
| CAN-2 | FDCAN2 | 4 个达妙关节电机 | CAN 或 CAN FD，待厂家协议确认 | 转向执行器控制节点 |
| CAN-3 | FDCAN3 | 2 台一拖二驱动器 | 经典 CAN 上的 CANopen | CANopen 主站 |

### 4.1 CAN-1：上位机与 BCM 共用 CAN FD

上位机和 BCM 共用一条物理 CAN FD，总线上的节点包括：上位机、BCM、VCU。BCM 的当前教育版设计见 [BCM 教育版总体设计](../BCM/总体设计.md)。

上位机向 VCU 下发的内容仅限底盘级命令：

- `vx`：车体纵向速度；
- `vy`：车体横向速度；
- `wz`：车体角速度；
- 底盘模式、使能、复位和速度限制；
- 可选的故障确认、参数读取和诊断请求。

BCM 与 VCU 交换的内容包括：

- BCM 电源域、继电器、灯光、风扇、电磁锁、推杆和 4G 状态；
- BCM 急停输入、车身故障和车身允许状态；
- VCU 故障、底盘使能、电子驻车和运行状态；
- 需要时的灯光、报警和车身联锁请求。

总线 ID 尚未冻结，但必须遵循“安全状态优先、控制命令次之、普通状态再次、诊断最低”的优先级原则。

CAN-1 必须画出实际线性拓扑、两个终端位置、每个支线长度、总线长度、参考地/屏蔽策略和 CAN FD 仲裁段/数据段速率。上位机、BCM、VCU 三节点不能以未校核的星形线束连接。控制报文必须包含来源、模式、序号、Alive Counter、端到端 CRC 和超时行为。

### 4.2 CAN-2：四个达妙转向关节电机

四个达妙关节电机使用同一条独立 CAN 总线，通过节点 ID 区分。

VCU 内部将它们抽象为四个独立转向轴：

```text
STEER_FL：左前转向
STEER_FR：右前转向
STEER_RL：左后转向
STEER_RR：右后转向
```

无论厂商协议最终使用经典 CAN 还是 CAN FD，应用层只使用统一的转向轴接口：

```text
输入：使能、目标角度、目标角速度、限流/限矩
反馈：实际角度、实际速度、电流、温度、状态、故障、在线状态
```

运动学模块不能直接拼接 CAN 帧；CAN 帧封装只允许位于“达妙电机协议适配层”。

### 4.3 CAN-3：两台一拖二 CANopen 驱动器

两台一拖二驱动器在物理上是两个控制器，但在 VCU 控制逻辑中必须视为四个独立驱动轴：

```text
DRIVE_FL：左前驱动轮
DRIVE_FR：右前驱动轮
DRIVE_RL：左后驱动轮
DRIVE_RR：右后驱动轮
```

驱动器通道与车轮的实际映射应在参数表中保存，不能硬编码在运动学算法内。

CANopen 侧预期使用以下功能：

- NMT 启动、停止和复位节点；
- 心跳监控与通信超时；
- SDO 参数配置；
- PDO 周期下发目标速度、使能和控制字；
- PDO 回传状态字、实际速度、电流、故障码和温度；
- 若驱动器支持 CiA 402，则按 CiA 402 状态机管理。

一台一拖二驱动器离线可能同时影响两个驱动轴。此类故障默认进入故障停车，不允许另外两个轮子继续维持正常运动。

### 4.4 每路 CAN 的硬件约束

每一路 CAN 均应具备：

- 1 颗板载 CAN FD 收发器；
- CANH/CANL 的 TVS 防护；
- 共模电感预留位；
- 120 Ω 终端电阻，建议用跳帽、拨码或电子开关配置；
- 接插件附近的保护与清晰网络标识；
- 收发器的待机/使能引脚接入 MCU 或安全控制逻辑；
- 与电机线束分区布线，避开 2.4 GHz 射频区域。

### 4.5 车载线束接口统一要求

VCU 的电源、三路 CAN、两线常闭急停、驱动器安全信号、BMS、超声波和 ToF 等正式对外车载线束，统一使用带锁止、防水和防呆结构的汽车连接器。UART 在本文中表示电气协议；BMS 和传感器 UART 物理上同样通过防水汽车连接器和线束连接，禁止使用 2.54mm 4 芯 UART 母头作为正式车载接口。

统一的是接口类别和设计规范，不要求所有接口采用相同针数或同一连接器系列。嘉立创商城已查到可用于 CAN/UART/急停等小信号的 `DL20023`/`JWPF` 方向型号，例如 `DL20023-2AS`、`DL20023-3AS`、`DL20023-4AS`，2 mm 间距、IPX7、页面常见额定约 3A，适合信号和小功率辅助电源，不适合 VCU 主 12V 输入。VCU 主电源应另选额定至少 5A、并按瞬态校核的防水汽车连接器。各接口的针数、端子规格、板端/线束端配对、线径、额定电流、温度范围、空腔堵头和防护等级必须随原理图、线束图和外壳设计一起冻结。

SWD、串口日志和生产测试仅保留为密封外壳内的测试焊盘、测试夹具或临时维护接口。nRF52840 到天线的 U.FL/IPEX 是板内专用 50Ω 射频通道；如需外置天线，应通过密封射频穿墙件连接，不作为多芯车载线束接口。

## 5. UART 架构

### 5.1 通道数量

| 设备 | 数量 | 连接方式 |
|---|---:|---|
| BMS | 1 | MCU 原生 UART，独占 |
| 超声波 | 8 | MAX14830 扩展 UART |
| 激光 ToF | 4 | MAX14830 扩展 UART |
| 合计 | 13 | 1 路原生 UART + 12 路扩展 UART |

### 5.2 MAX14830 扩展方案

```text
SPI_UART（MCU SPI + DMA）
├── MAX14830_A：USONIC_1 ~ USONIC_4
├── MAX14830_B：USONIC_5 ~ USONIC_8
└── MAX14830_C：TOF_1 ~ TOF_4
```

三颗 MAX14830 共用 SPI 时钟和数据线，每颗使用独立片选。每颗芯片应至少提供独立中断输入；中断触发后由 DMA/软件读取 FIFO，避免轮询 12 路串口造成 CPU 占用和数据丢失。

每颗 MAX14830 还需要按照数据手册配置晶振或外部参考时钟、`VL/VEXT/VA/V18` 电源与去耦、`RST` 默认状态和开漏 `IRQ` 上拉。VEXT 是 UART/GPIO 接口电源，不能遗漏；启用内部 LDO 时 V18 只接规定去耦，不接 3V3。三颗芯片可否共享时钟、时钟扇出和走线方式必须经过时序/信号完整性核对，不能只画 SPI 与 UART 引脚。固件应在启动时检查时钟就绪、器件复位状态和各 UART FIFO 自检。

UART 传感器协议层必须维护每一路的：

- 接收缓存与帧同步；
- 长度、校验和或 CRC；
- 最后有效数据时间；
- 在线/离线状态；
- 异常帧计数；
- 距离有效性和超量程状态。

### 5.3 线束抗干扰原则

MAX14830 提供的是逻辑电平 UART，并不等于车载远距离物理层。若超声波或 ToF 线束跨越电机、电池和驱动器区域，应根据实际线长、传感器供电和协议能力选择以下措施：

- 采用屏蔽双绞线并保证可靠共地；
- 在接插件旁加入 ESD/浪涌保护；
- 传感器为 5 V UART 时增加电平转换；
- 对长线优先评估 UART 转 RS-485 或传感器子板汇聚方案。

无论最终采用逻辑电平 UART、RS-485 或传感器子板汇聚，VCU 板到车载线束的正式物理接口都使用防水汽车连接器；不得为了 UART 方便而增加对外 4 芯母头。

每一类传感器的电平、波特率、最大线长、供电、浪涌/ESD 等级和物理层必须在 Gerber 前冻结。只写“预留 RS-485”不足以放行一个将逻辑 UART 直接接入长车载线束的原理图。

## 6. 2.4 GHz 无线遥控链路

### 6.1 模块要求

VCU 板内置基于 `nRF52840` 的无线模块，要求选择带 U.FL/IPEX 外置天线座的版本。

`nRF52840` 是需要独立固件的可编程 SoC，不是天然提供固定 SPI 从机协议的无线收发器。必须先选定具体模块并确认引脚、射频认证/区域、供电峰值和生命周期，同时建立 nRF 固件工程和 STM32↔nRF 应用协议。

若所选模块和自研固件采用 SPI 从机接口，主控之间至少连接：

```text
SPI_SCK / SPI_MOSI / SPI_MISO / RF_CS
RF_IRQ
RF_RESET
RF_ENABLE
3.3V_RF / GND
```

还必须为 nRF 模块保留独立 SWD、复位和量产测试点，并定义双 MCU 的版本兼容、升级、超时、复位恢复和故障安全行为。模块未选定前，`RF_IRQ/RF_ENABLE` 等信号不能被当作已冻结接口。

优先选择模块本体自带 U.FL/IPEX 的版本并放在 PCB 边缘，此时 VCU 载板不再自行布设 2.4GHz 射频线。只有当所选模块明确提供 RF 引脚、需要在载板连接 U.FL/IPEX 时，才按模块参考设计完成 50Ω 阻抗、匹配网络、连续参考地和禁布区，并重新评估模块/整机射频认证。射频区域始终远离 CAN 收发器、电源开关节点与电机接口。

U.FL/IPEX 仅用于 VCU 板内到天线或密封射频穿墙件的同轴连接，不作为普通车载线束接口。

### 6.2 无线协议原则

无线链路使用 nRF52840 的低延迟私有 2.4 GHz 协议，例如 ESB 或等价的自定义可靠报文机制，而不将普通 BLE 配对或 Wi-Fi 作为运动控制链路。

建议遥控器周期发送：

```text
遥控器设备 ID
心跳计数器
序号
使能/死手开关状态
急停状态
vx / vy / wz 或摇杆量
模式选择
CRC
```

VCU 应回传：

```text
VCU 在线状态
底盘模式
急停锁存状态
电池摘要
电机故障摘要
链路质量
CRC
```

仅当 `RADIO` 控制源已经人工选择、配对成功并进入武装状态时，无线遥控器急停、死手开关释放、无线链路丢失、序号异常或 CRC 连续失败才触发无线安全停车。处于上位机模式或无线未武装时，不得因为没有收到无线心跳而阻止车辆自检、进入 READY 或执行有线控制。

### 6.3 无线急停的安全边界

教育版可将已武装无线遥控器的急停实现为“无线安全停止”，即收到急停报文、死手开关释放或心跳超时后立即进入 `ESTOP_LATCHED` 状态。

但通用 2.4 GHz 模块不是经过功能安全认证的无线急停设备，不能替代 VCU 本地两线硬件急停。若后续产品需要满足安全认证或人员保护等级，应使用专用安全无线控制系统或冗余安全接收架构。

## 7. 急停、电子驻车与安全状态机

### 7.1 本地急停接口

VCU 板必须引出独立两线急停接口，连接外部急停按钮的常闭触点：

```text
VCU_ESTOP_NC+ ── 急停按钮常闭触点 ── VCU_ESTOP_NC-
```

该急停回路的正式对外接口使用防水汽车连接器，并按断线即急停的原则选择端子、锁止和线束固定方式。

正常状态回路闭合；按下急停、接插件脱落或导线断开都视为急停。

该接口不能只进入 MCU 的普通 GPIO。它必须同时进入独立硬件安全链路，使 MCU 卡死或 CAN 失效时仍能阻止电机继续运动。

单通道两线常闭回路无法诊断线路短接，不等同于经过认证的功能安全急停。它只可作为受控、低速、有人监护的教育验证基线；若设备可能接近人员或需要安全等级，必须依据风险评估使用双通道安全继电器/安全控制器、强制导向接触器和反馈监控。

### 7.2 急停硬件动作

```text
本地急停回路断开
        │
        ▼
硬件安全门控
├── 关闭四个驱动轴的硬件使能/STO 或切断其安全接触器
├── 关闭四个转向轴的硬件使能/STO 或切断其安全接触器
├── 置位可用的 Quick Stop / Brake 请求
├── 禁止新的驱动输出
├── 向 MCU 提供 ESTOP_ACTIVE 状态
└── 保持 VCU 逻辑电源，便于故障记录和上报
```

硬件原理图应预留每台驱动器的如下安全信号，实际高低电平和电气类型待驱动器手册确认：

```text
DRIVE_A_ENABLE / DRIVE_B_ENABLE
DRIVE_A_QUICK_STOP / DRIVE_B_QUICK_STOP
DRIVE_A_FAULT / DRIVE_B_FAULT
DRIVE_A_READY / DRIVE_B_READY
DRIVE_A_RESET / DRIVE_B_RESET
```

还必须为四个转向执行器冻结硬件安全路径，例如 `STEER_SAFETY_ENABLE`、厂家硬件 Enable/STO，或切断转向动力的安全接触器。若达妙转向电机只能通过 CAN 停止，则当前选型不能满足“MCU/CAN 失效时仍阻止运动”的急停目标，必须调整系统电源/接触器架构或更换执行器方案。

CANopen 的 Quick Stop、禁用电压或目标速度归零只能作为补充动作，不能作为唯一急停手段。

### 7.3 急停软件状态

系统至少包含以下状态：

```text
INIT → SELF_CHECK → READY → ENABLED → RUN
                              │
                              ├── 通信/设备异常 → FAULT
                              └── 本地急停/已武装无线急停或失联 → ESTOP_LATCHED
```

进入 `ESTOP_LATCHED` 后必须执行：

1. 清除所有 `vx / vy / wz`、转向和驱动目标；
2. 关闭正常电机使能；
3. 对驱动器发出电子刹车或快速停止请求；
4. 停止下发正常运动目标，但继续发送驱动器要求的禁能、Quick Stop 或安全状态报文；
5. 忽略上位机、BCM 和无线遥控器后续运动命令；
6. 上报急停来源和锁存状态；
7. 禁止在急停按钮松开或无线恢复后自动重启。

退出急停只能采用显式流程：

```text
急停物理回路恢复
        ↓
若本次由无线触发：遥控器急停释放、死手开关释放后重新确认且链路正常
        ↓
人工复位命令
        ↓
设备重新自检
        ↓
READY
        ↓
重新使能后才允许 RUN
```

“电子驻车”的具体实现由驱动器能力决定。必须先由危害分析确定急停后是受控减速、保持力矩还是切断动力；未经验证不能把 Quick Stop、Brake 或断电默认视为安全。厂家协议明确后，必须实测急停减速度、停止距离、保持力、转向响应和断电行为。

## 8. 看门狗与失控恢复

### 8.1 内部看门狗

`STM32G474QET6TR` 内置两个看门狗：

- IWDG：独立看门狗，使用独立低速时钟，主时钟或软件卡死时仍可复位 MCU；
- WWDG：窗口看门狗，可检测过早或过晚刷新。

IWDG 是必须启用的主看门狗。量产配置中应考虑将其设置为上电即由硬件启用，避免程序异常时被错误关闭。

### 8.2 看门狗管理原则

禁止由任意单一通信任务直接喂狗。必须由专门的安全监督任务汇总安全关键任务心跳后，统一决定是否刷新 IWDG。BMS、超声波、ToF 等非安全关键服务故障应优先进入降级状态并上报，不应因为单个非关键外设掉线而持续复位整机。

```text
关键任务心跳
├── 底盘主控制循环
├── 转向电机通信
├── CANopen 驱动通信
├── 当前已选控制源通信
├── 执行器反馈与超时管理
└── 安全状态机
        │
        ▼
监督任务确认全部正常
        │
        ├── 正常：刷新 IWDG
        └── 异常：停止刷新，等待 IWDG 复位
```

建议初始 IWDG 超时设在 100~300 ms 区间，再根据实际总线周期和软件运行时间测试收敛。复位后必须读取并记录复位原因。

### 8.3 硬件安全门控

看门狗可以恢复 MCU，但不能单独保证车辆安全。例如 MCU 卡死时，电机使能可能仍维持在原状态。

因此应预留外部硬件看门狗/安全监督器，其输出参与 `SAFETY_ENABLE` 门控：

```text
MCU 周期性硬件心跳 ──▶ 外部监督器
                                │
本地急停 ───────────────────────┼──▶ SAFETY_ENABLE
                                │        │
电源异常 / 驱动器故障 ───────────┘        ▼
                              驱动轴使能/STO + 转向轴安全接触器/使能
```

任何一项失效都应使 `SAFETY_ENABLE` 进入安全态。

## 9. 四轮四转控制边界

### 9.1 车体速度指令

上位机或遥控器只提供车体速度：

```text
vx：前后速度
vy：左右速度
wz：绕车体 Z 轴的角速度
```

VCU 只保存“可配置、可标定”的底盘几何参数，首版不写死任何四轮实车尺寸。轴距、轮距、轮胎有效半径、四轮安装坐标、转向零位和方向，全部标记为待实车测量/标定，并通过参数表或 Flash 配置写入：

坐标系必须在通信协议和标定文档中统一：推荐使用右手车体坐标，`+x` 向前、`+y` 向左、`+z` 向上，`+wz` 为逆时针；速度使用 m/s、角速度使用 rad/s、角度使用 rad。所有电机方向、编码器方向和安装坐标均以这一约定标定，禁止不同模块自行定义正负号。

- 四个车轮的坐标 `(x_i, y_i)`；
- 由实车测量得到的轴距、轮距和轮胎有效半径；
- 每个转向轴的零位偏置和正方向；
- 每个驱动轴的正方向、减速比和速度上限；
- 最大转向角、最大轮速、加速度和减速度。

四个转向轴和四个驱动轴的逻辑名称可以固定为 `FL/FR/RL/RR`，但不代表预设了它们的几何尺寸或左右正负方向；方向、零位和映射必须在实车标定后写入配置。

### 9.2 基础运动学

对第 `i` 个车轮：

```text
vxi = vx - wz × yi
vyi = vy + wz × xi

steer_angle_i = atan2(vyi, vxi)
wheel_speed_i = sqrt(vxi² + vyi²)
```

`wheel_speed_i` 是轮缘线速度幅值；下发给电机前必须根据角度翻转结果赋予正负号，再按实测有效轮胎半径和减速比转换为轴角速度。`sqrt(vxi²+vyi²)` 接近零时不得直接使用不确定的 `atan2(0,0)`，应保持上一次安全转角或进入预定义静止姿态。

实际控制还必须增加：

- 转向零位补偿；
- 目标角度限幅；
- 转向角翻转与轮速反向优化；
- 低速角度保持；
- 转向未到位时的轮速降额；
- 加速度与减速度斜坡；
- 任一轮超限时对全部轮速进行等比例缩放，不能逐轮独立削顶破坏车体运动方向；
- 驱动/转向反馈超时；
- 单轴、双轴和节点级故障处理。

8 路超声波和 4 路 ToF 默认仅作为辅助感知/避障输入，不得在未经安全认证和诊断覆盖分析时作为唯一人员防护传感器。其掉线、盲区、互扰和超量程行为必须在整车状态机中明确。

## 11. 初始周期建议

| 功能 | 初始建议周期 | 说明 |
|---|---:|---|
| 四轮四转解算 | 100 Hz | 根据实测可提高至 200 Hz |
| 转向目标下发 | 100 Hz | 由达妙协议能力最终确认 |
| 驱动轮目标下发 | 50~100 Hz | CANopen PDO 周期 |
| 电机反馈处理 | 50~100 Hz | 依据总线负载调整 |
| 上位机速度指令 | 20~50 Hz | 必须含心跳/序号 |
| 无线遥控器心跳 | 50~100 Hz | 丢失超时进入无线安全停车 |
| BMS 通信 | 10~50 Hz | 视 BMS 协议而定 |
| 超声波/ToF | 10~50 Hz | 按传感器刷新率与串口带宽安排 |
| 安全监督 | 100~500 Hz | 检查急停、故障、通信超时与任务心跳 |

CAN 总线长期平均负载建议控制在 60% 以下，为故障帧、诊断帧和重发预留空间。

## 12. 需要在原理图阶段保留的接口

| 类别 | 建议保留内容 |
|---|---|
| 调试 | SWD、NRST、BOOT、串口日志测试焊盘或板内维护接口；不设置对外 4 芯 UART 母头 |
| CAN | 三路 CANH/CANL、终端电阻配置、收发器待机控制和防水汽车连接器 |
| 电机安全 | 四个驱动轴的 Enable/STO、Quick Stop/Brake、Fault、Ready、Reset，以及四个转向轴的硬件安全使能/STO或安全接触器控制与反馈 |
| 急停 | 两线常闭急停接口、防水汽车连接器、本地急停状态输出/指示灯 |
| 无线 | 具体 nRF52840 模块的 SPI/其它主机接口、IRQ、Reset、独立 SWD、量产测试点和 U.FL/IPEX 天线座 |
| UART | BMS 独立接口、12 路传感器 UART 接口、防水汽车连接器、保护与电平兼容设计 |
| 电源 | 逻辑电源、射频干净 3.3 V、CAN 收发器电源、输入反接/浪涌保护 |
| 维护 | 复位键、状态 LED、故障 LED、量产测试点 |

VCU 主电源接口按 12V、3A 连续、5A 短时峰值校核；CAN/UART/急停/传感器接口按小信号连接器的端子额定和线束环境分别校核。四个驱动轮和四个转向执行器的动力电源不经过 VCU PCB。

以下内容在厂家协议提供后冻结，不影响当前硬件总体架构：

- 达妙电机使用经典 CAN 还是 CAN FD、波特率、节点 ID、控制模式和故障语义；
- 两台一拖二驱动器的 CANopen 节点模型、PDO 映射、CiA 402 支持情况、Quick Stop 与电子驻车能力；

- 无线遥控器的具体摇杆、使能、急停和配对策略；

- 130 mm × 90 mm 板框内的安装孔、连接器朝向、线束弯曲半径和外壳干涉关系。

## 14. 最终架构结论

本 VCU 教育版采用 `STM32G474QET6TR` 作为主控，以三路原生 FDCAN 覆盖上位机/BCM、转向和 CANopen 驱动网络；使用 3 颗 `MAX14830` 完成 12 路 UART 传感器扩展；使用带 U.FL/IPEX 外置天线的 `nRF52840` 模块支持后续自研 2.4 GHz 遥控器。

安全上以本地硬件急停为最高优先级，并要求四个驱动轴和四个转向轴都进入经验证的安全态；只通过 CAN 发停止命令不满足这一目标。无线急停和链路丢失仅在无线控制已选择并武装时触发同一套锁存停车策略。急停发生后，VCU 进入 `ESTOP_LATCHED`，拒绝正常运动指令，持续维持必要的禁能/安全报文，直至触发源恢复、人工复位、自检和重新使能完成。
