DM-J10010L-2EC 资料目录不是可编译软件例程。其 README 只说明资料发布目录；本项目据 S10 整理了 `VCU/软件程序/protocols/DM_J10010L_2EC_CAN.md` 作为实现输入，但没有据此宣称固件完成或实物联调通过。

四台转向电机接公共 CAN2 前，必须一次只连接一台完成唯一 ESC_ID/MST_ID 配置、存储、重启和读回。反馈 D0 的“低 8 位 ID”与 `ERR<<4` 会发生位重叠，0x50/0x51 的位置含义也存在文本冲突；厂家未澄清前，软件不得选择一种解释后静默运行。力位混控段 99.74A 与参数表 95A 冲突，限流采用经厂家确认且更保守的值，并从低能量台架开始。

商户补充口述称 MSSD “只支持 CAN2.0，数据格式跟 CANopen SDO 类似，支持电机状态主动上报”。前两项与 S08 相符，但“类似 SDO”不等于完整 CANopen；主动上报在现有 S08 中没有报文定义，仍需取得正式表格。软件不得启用通用 CANopen/CiA 402 栈后假定可直接通信。

商户对推杆的口述可作为选型线索：两根电机线无固定正负，换极改变伸缩方向，断电停止，两端据称各有内置行程开关。这里的“不分正负”只表示没有永久正负定义，不表示可以接交流电、随意热插拔或不经 H 桥死区直接换向。没有推杆型号规格书之前，不把“到端自动断电”写成已验证；尤其还需确认到端后反向是否可退出、限位开关额定和失效方式、断电中停是否会在载荷下回驱。

原始文件保持不改，来源 URL 和 SHA256 在附录及 CSV。S02 为厂家文档镜像，不是本次从 NXP 取得的最新版；采购前核验版本和可持续供货。S05/S06 版本由 Git blob 固定，不用“master 永远不会变”的假设。

外部资料下载在本次制作中遇到审批服务用量限制，后续所需资料未能取得；这不是器件通过/不通过的判断。不得绕过授权下载，也不把缺失文件假称已读。可由使用方提供 PDF，或待授权服务恢复再补核。

## 4. 评审与关闭工作流

收到输入 → 核对型号/版本 → 更新候选物料与连接页 → 用具体数据重算 → 更新 Pinmap/接口图 → 独立复核 → 重建 PDF/DOCX → CAD ERC/DRC → 样板验证。任何影响腔号/电压/极性的变更都升级硬件/线束版本并作旧版停用说明。

只有纸面文件完整不能证明实际样板可靠。下一步应是依据本包完成有 H 标识的原理图草图，并关闭 H01～H16；不能直接把本包交板厂要求投板。

## 5. 重建与自检

1. 使用带 reportlab、python-docx、pypdf 的 Python 依次运行 `工具/generate_data.py`、`工具/generate_connections.py`，产生数据表、附录和逐焊盘连接册。
2. 运行 `工具/build_print.py` 生成主手册 PDF/DOCX，再运行 `工具/build_workbook.py` 生成完整横向作业册，最后运行 `工具/verify_package.py`。
3. 查看数据校验与导出报告；人工抽查封面、正文密集表、228 脚附录和最后签字表，确认没有截字/缺页。
4. 改 GPIO 必须改工具中的单一分配源，并同步相应正文概要；改电路需更新相关计算、BOM、测试和变更日志。

工具不会验证外部器件电平、保护协调、真实 CAD 连接和硬件性能。生成通过只表示文档内部的有限检查通过。
