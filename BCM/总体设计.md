# BCM 教育版总体设计

**文档状态：方案定稿**  
**版本：V1.0**  
**日期：2026-09-15**

## 1. 设计目标

本 BCM 用于教育版四轮四转机器人底盘，负责车身灯光、上位机电源域、风扇、推杆、电磁锁、温湿度监测、4G 唤醒和 CAN 通信。

本版本采用 STM32 主控和继电器输出方案，取消原设计中的 20 路智能高边灯光输出，保留一条电磁锁智能高边通道和一套 MC33926 推杆 H 桥。

机械臂控制器不由 BCM 直接控制，仅预留 CAN 接口。

## 2. 总体结论

### 2.1 主控

| 项目 | 定案内容 |
|---|---|
| MCU | STM32G491VET6 |
| 封装 | LQFP-100 |
| 主频 | 最高 170 MHz |
| Flash | 512 KB |
| 主要资源 | 双 FDCAN、ADC、SPI、I2C、UART、DMA、定时器 |
| 下载升级 | SWD + CAN Bootloader |

### 2.2 电源架构

BCM 只有一个外部电源输入：**12V**。

车辆 48～54V 电池到 12V 的大功率转换由外部 DCDC 完成。BCM 板上只完成低压电源转换和负载控制。

```text
48～54V 电池
      │
      ▼
外部大功率 DCDC
      │ 12V
      ▼
BCM 单路 12V 输入
      ├── K1～K8 继电器触点及 12V 负载
      ├── 电磁锁智能高边
      ├── MC33926 推杆 H 桥
      ├── 12V → 4.0V：EG800Z-GL
      ├── 12V → 5V：外设电源
      └── 5V → 3.3V：STM32、SHT31、逻辑电路
```

板载降压必须使用 DC/DC 或稳压模块，不能使用电阻分压为 MCU、4G 或其他负载供电。

外部 12V DCDC 建议至少满足 60A 输出能力，推荐按 70～80A 峰值能力选型。

### 2.3 继电器数量

共使用 8 路 12V 继电器：

| 继电器 | 控制对象 | 设计电流 |
|---|---|---:|
| K1 | 上位机、功放、显示板、摄像头组、路由器 | 30A |
| K2 | 风扇 | 3A |
| K3 | 前灯一体 | 3A |
| K4 | 后灯一体 | 3A |
| K5 | 左转向灯 | 3A |
| K6 | 右转向灯 | 3A |
| K7 | 自动驾驶灯 | 3A |
| K8 | 巡逻灯 | 3A |

继电器统一采用 12V 线圈。K1 按 30A 设计，K2～K8 使用 12V、20A 级继电器。

所有继电器线圈由 STM32 通过 MOS 管低边驱动，并在线圈两端增加续流保护。

本版本不设置支路保险，不设置继电器触点反馈，也不检测 K1 输出电压。上游电源保护、主线保护和负载自身保护由整车电源系统及负载端负责。

## 3. 功率预算

| 功能 | 最大设计电流 |
|---|---:|
| K1 上位机电源域 | 30A |
| K2 风扇 | 3A |
| K3～K8 六路灯光 | 18A |
| 电磁锁智能高边 | 5A 预留，实际约 1A |
| 推杆 MC33926 | 5A 预留，实际约 1A |
| 合计 | 约 61A |

BCM 的 12V 输入连接器、主电源铜线、继电器公共电源区域和 PCB 高电流走线按约 65～70A 峰值能力设计。K1 主回路使用加宽铜箔、铜排或专用大电流连接结构，不能使用普通小电流信号走线。

## 4. 负载和控制逻辑

### 4.1 K1 上位机电源域

K1 同时给以下设备供电：

- 上位机
- 功放
- 显示板
- 摄像头组
- 路由器

K1 设计电流为 30A。K1 采用一个继电器统一控制，不再为上述设备分别设置继电器。

EG800Z-GL 不由 K1 控制，使用 BCM 常电待机电源单独供电，以支持远程唤醒。

### 4.2 风扇

风扇由 K2 控制。

- 正常情况下由温度、湿度阈值控制
- 阈值可由上位机设置
- 必须设置开启和关闭回差
- 支持 CAN 强制开启
- 任一关键温湿度传感器掉线时，风扇默认开启
- K2 不做触点反馈

推荐控制优先级：

```text
急停输出策略（见第 7 章）
        > 传感器故障强制开启
        > CAN 强制开启
        > 温湿度自动控制
```

### 4.3 灯光

灯光全部采用继电器通断控制，不由 STM32 生成闪烁波形。

- 前灯和后灯允许同时开启
- 左转和右转允许同时开启，实现双闪
- 转向灯为通电自闪型
- 自动驾驶灯在自动驾驶模式下自动开启
- 巡逻灯由上位机控制
- 不实现灯光闪烁算法
- 不保留三色模式指示灯
- 上装灯取消

### 4.4 电磁锁

电磁锁采用 1 路独立智能高边开关：

- 实际工作电流约 1A
- 按 5A 能力预留
- 通电上锁
- 断电开锁
- 继电器急停策略不适用于电磁锁，电磁锁由独立智能高边控制
- 过流、短路或急停时立即关闭

电磁锁为四根线：

```text
两根：锁电源线
两根：干节点锁状态反馈线
```

反馈输入不向锁反馈线主动供电，采用隔离/限流/上拉后的数字输入方式。默认按“上锁完成后干节点闭合”处理，并在软件中保留有效电平配置和消抖。

### 4.5 上盖推杆

推杆使用 MC33926 H 桥控制，电机只有两根线，通过交换正负极改变方向。

```text
OPEN   ：正向运行
CLOSE  ：反向运行
STOP   ：停止
```

推杆实际电流约 1A，堵转电流不超过 5A。

“不自动反向”的含义：

- 开启过程中不会自动切换为关闭
- 关闭过程中不会自动切换为开启
- 过流、堵转或超时后只停止，不自动反向
- 收到新的反向命令时，先停止，再经过短暂死区，最后允许改变方向

推杆保留 MC33926 电流反馈 ADC，用于过流、堵转和动作超时判断。

### 4.6 机械臂

机械臂不由 BCM 直接控制，不占用继电器和高边输出资源，仅预留 CAN 接口供后续扩展。

## 5. 通信和接口

### 5.1 主干 CAN 和预留 CAN

STM32G491 的两路 FDCAN 分配如下：

| 接口 | 用途 |
|---|---|
| CAN1 | 主干 CAN FD |
| CAN2 | 预留 CAN，后续可接机械臂等设备 |

CAN 报文 ID、信号定义、周期、超时时间、CRC 和 Alive Counter 暂不冻结，后续根据整车通信协议确定。软件先提供统一 CAN 驱动、报文队列、信号打包和解包接口。

### 5.2 4G 模块

模块：EG800Z-GL。

软件采用：

- UART DMA 接收
- 环形缓冲区
- 非阻塞 AT 命令状态机
- AT 命令队列
- 响应匹配和超时重试
- 远程唤醒
- 状态通信

本版本暂不实现 4G OTA。

### 5.3 温湿度传感器

两个 SHT31 共用一路 I2C：

| 地址 | 用途 |
|---|---|
| 0x44 | 舱内温湿度 |
| 0x45 | 控制板区域温湿度 |

驱动需要包含 CRC 校验、掉线检测、合理范围检查、数据滤波和传感器状态管理。

### 5.4 唤醒输入

支持三类唤醒来源：

- EG800Z-GL 4G 唤醒
- 主干 CAN 唤醒
- 外部唤醒输入

外部唤醒输入采用带限流、滤波和过压保护的数字输入电路。

### 5.5 其他输入

保留以下输入功能：

- 急停状态输入
- 电磁锁干节点反馈输入
- 推杆 MC33926 故障输入
- 推杆电流 ADC 输入

### 5.6 车载线束接口统一要求

BCM 的 12V 输入、K1～K8 负载输出、电磁锁、推杆、CAN、外部唤醒和舱内传感器等正式对外车载线束，统一使用带锁止、防水和防呆结构的汽车连接器。接口类别已经冻结；具体系列、针数、端子规格、板端/线束端配对和线束线径待原理图、PCB 外形和安装空间确定后冻结。

12V 主输入和 K1 30A 回路不得与低压信号共用普通小电流连接器，必须使用独立的大电流防水汽车连接器或等效的大电流防水连接结构，并按 65～70A 峰值输入路径、30A K1 回路和实际线束温升完成校核。

UART 仅用于 BCM 板内 MCU 与 EG800Z-GL 模块之间的通信，不作为 4 芯 UART 母头对外引出。SWD、串口日志和生产测试仅保留为密封外壳内的测试焊盘、测试夹具或临时维护接口。若舱内 SHT31 不安装在 BCM 板上，不能把裸 I2C 作为长距离车载线束直接引出；应采用短线本地传感器子板或经评估的抗干扰转换方案，且车载线束端仍使用防水汽车连接器。

4G 天线如需出壳，板内可使用 U.FL/IPEX 等专用 50Ω 射频连接，外壳处使用密封射频穿墙件；该射频通道不替代也不使用多芯车载线束连接器。

## 6. 状态机

BCM 主状态建议如下：

```text
INIT → SELF_CHECK → STANDBY
                    │
                    ├── 唤醒事件 → WAKE_REQUEST → SELF_CHECK → POWER_ON → NORMAL_RUN
                    │                                            │             ├── DEGRADED_RUN
                    │                                            │             └── FAULT
                    └── 休眠条件 → SLEEP
```

STANDBY 和 SLEEP 都可由 4G、主干 CAN 或外部唤醒输入触发并进入 `WAKE_REQUEST`，随后执行自检；这样与待机/休眠阶段保留的唤醒能力保持一致。

### 6.1 待机

待机状态只保持必要的 MCU、监控电路和 EG800Z-GL 电源。K1～K8 默认断开，电磁锁和推杆默认关闭。

### 6.2 唤醒

4G、主干 CAN 或外部唤醒输入产生有效事件后，BCM 唤醒并执行自检。自检完成后，根据上位机和整车状态控制 K1～K8。

### 6.3 运行

运行状态中执行继电器控制、灯光逻辑、风扇控制、推杆控制、电磁锁控制、CAN 通信和 4G 状态通信。

### 6.4 休眠

满足休眠条件时：

- K1～K8 断开
- 电磁锁高边关闭
- 推杆停止
- 保留 MCU 低功耗唤醒能力
- 保留 EG800Z-GL 远程唤醒能力

## 7. 故障策略

按教育版默认故障策略执行：

| 故障 | 处理 |
|---|---|
| MCU 复位 | 所有继电器默认断开，电磁锁关闭，推杆停止 |
| 急停 | K1、K3～K8 断开，推杆停止，电磁锁关闭；K2 仅保留温度保护或传感器故障下的强制散热，不接受 CAN 强制开启 |
| 电磁锁过流/短路 | 立即关闭并记录故障 |
| 推杆过流/堵转 | 立即停止，不自动反向 |
| 推杆动作超时 | 停止并记录故障 |
| 温湿度传感器掉线 | 风扇默认开启 |
| 4G 无响应 | 退出当前 AT 状态，重试或复位模块 |
| CAN 超时 | 相关受控功能进入安全默认状态 |
| 看门狗超时 | 硬件复位 MCU |

由于 K1～K8 不做触点反馈，软件不能确认继电器触点是否实际吸合，只记录控制命令和继电器线圈驱动状态。

## 8. 电源监控和保护

教育版不采用 FS26，采用成本更低的分立方案：

- 12V 输入 TVS 和反接保护
- 12V→5V DC/DC
- 12V→4.0V、≥3A 的 4G 专用 DC/DC
- 5V→3.3V 稳压
- 3.3V 电源监控和复位芯片
- 独立硬件看门狗
- MCU ADC 监测必要的电源电压

本版本不要求正式 EMC/ESD 认证测试，但仍保留基础的 TVS、输入滤波、接口限流和 ESD 防护设计。

## 9. 软件架构

采用轻量化 FreeRTOS 和事件驱动相结合的结构，避免为每个小功能单独创建任务。

```text
Bootloader
├── SWD 下载
└── CAN Bootloader

BSP/HAL
├── GPIO
├── FDCAN
├── UART DMA
├── SPI
├── I2C
├── ADC
├── Timer
└── Low Power

Drivers
├── Relay Driver
├── Smart High-Side Lock Driver
├── MC33926 Driver
├── SHT31 Driver
├── EG800Z Driver
└── Watchdog/Supervisor Driver

Services
├── Event Manager
├── Fault Manager
├── Parameter Manager
├── NVM Storage
└── Diagnostic Manager

Application
├── BCM State Manager
├── Power Manager
├── Light Manager
├── Fan Manager
├── Lock Manager
├── Actuator Manager
└── Wake/Sleep Manager
```

建议只保留四类任务：

| 任务 | 主要职责 |
|---|---|
| Safety/Control Task | 1ms 安全输入、继电器输出、推杆和电磁锁保护 |
| CAN Task | CAN 接收、发送、超时和事件分发 |
| 4G Task | EG800Z AT 状态机和远程通信 |
| Service Task | 温湿度、诊断、参数、故障记录和低功耗管理 |

软件要求：

- 静态内存分配
- DMA 优先
- 中断中只做采样、入队和置位，不执行复杂业务
- 所有输出通过统一接口控制，不允许业务层直接操作 GPIO
- 所有参数具有默认值、范围检查和版本管理
- 故障记录支持事件触发保存

## 10. 统一输出接口

应用层使用逻辑通道，不直接绑定 MCU 引脚：

```text
RELAY_UPPER_COMPUTER_DOMAIN
RELAY_FAN
RELAY_FRONT_LIGHT
RELAY_REAR_LIGHT
RELAY_LEFT_TURN
RELAY_RIGHT_TURN
RELAY_AUTONOMOUS_LIGHT
RELAY_PATROL_LIGHT
LOCK_HIGH_SIDE
ACTUATOR_MC33926
```

推荐的控制接口包括：

```text
Relay_Set(channel, enable)
Relay_GetCommand(channel)
Lock_Set(enable)
Lock_GetFeedback()
Actuator_Open()
Actuator_Close()
Actuator_Stop()
Actuator_GetCurrent()
Fan_SetMode(mode)
```

## 11. 环境和结构要求

- 工作温度：-15～55℃
- 具备防泼溅能力
- 建议采用带密封外壳
- PCB 建议做三防涂层
- 正式对外车载线束统一使用防水汽车连接器；具体系列和针数根据底盘安装空间后续确定
- 高电流输入和 K1 回路使用专用大电流防水汽车连接器或等效大电流防水连接结构，并配合加宽铜结构

裸 PCB 本身不能等同于防泼溅结构，最终防护能力由外壳、密封件、连接器和 PCB 涂层共同决定。

## 12. 当前不冻结的内容

以下内容不影响本版总体架构，待后续项目资料确定：

1. CAN 报文 ID、信号定义、周期和超时值
2. CAN 速率和是否启用 CAN FD 数据段
3. 电磁锁干节点实际为常开还是常闭
4. 具体继电器型号，以及防水汽车连接器的系列、针数、端子规格和板端/线束端配对
5. 外部 48～54V 转 12V DCDC 的最终型号
6. PCB 尺寸、安装孔和线束接口定义
7. 各继电器和负载的最终线束规格

除上述接口细节外，教育版 BCM 的功能范围、主控、电源拓扑、继电器数量、功率分配和软件总体框架已经定稿。
