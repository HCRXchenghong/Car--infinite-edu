# BCM 固件工程状态

当前目录尚无可编译、可烧录的 BCM 固件。总体设计中的 FreeRTOS 分层只是设计输入，不代表固件已经实现。

## 建立工程前的入口条件

- STM32G491 完整 Pinmap、时钟树、DMA/中断优先级和所有输出的复位默认态已冻结；
- CAN 报文字典、CRC、Alive Counter、超时、版本兼容和 CAN 唤醒流程已冻结；
- K1～K8、锁、推杆、4G 和板载电源的真实功率预算及支路保护已经闭合；
- EG800Z、SHT31、MC33926 和智能高边的正式器件资料及电气接口已归档；
- 4G 远程请求的身份认证、加密、重放保护和权限规则已定义。

## 建议工程结构

```text
BCM/软件程序/
├── CMakeLists.txt 或工程配置
├── README.md
├── app/             BCM 状态机、灯光、风扇、锁、推杆和电源管理
├── services/        CAN、4G、参数、诊断、故障记录和低功耗
├── protocols/       主干 CAN 与 4G 应用协议
├── drivers/         继电器、高边、MC33926、SHT31、EG800Z、看门狗
├── bsp/             板级 Pinmap、时钟、电源、唤醒和测试点
├── bootloader/      镜像校验、版本、断电恢复和回滚
├── tests/           单元测试、协议回放和故障注入
└── tools/           参数生成、日志解析和产测工具
```

## 最低质量要求

- 固定工具链和依赖版本，构建可重复；
- 编译警告视为错误，启用静态分析和格式检查；
- 所有输出只能通过统一驱动接口，业务层不得直接写 GPIO；
- MCU 复位、下载、看门狗复位和低功耗切换期间，继电器、锁和推杆保持安全默认态；
- 推杆具有过流、堵转、超时、反向死区和故障锁存测试；
- 风扇回差、传感器掉线默认开启、急停输出策略和 CAN 超时具有单元测试；
- 4G AT 驱动非阻塞，网络输入在认证和防重放通过前不能改变输出；
- 在真实负载前使用假负载完成短路、断线、过温、欠压、复位和组合输出测试。
